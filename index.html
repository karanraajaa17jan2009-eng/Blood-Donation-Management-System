🔷 Peter Chen ER Notation Diagram (Textbook Style)

Classical entity-relationship model with Rectangles (Entity Sets), Diamonds (Relationships), and Ovals (Attributes with Primary Keys underlined).

BLOOD_STOCK Master
  • [PK] blood_group VARCHAR(5)
  • available_units INT ≥ 0
  • minimum_threshold INT ≥ 0
  • last_updated DATETIME
DONOR Master
  • [PK] donor_id INTEGER (AI)
  • name VARCHAR(100)
  • age 18-65
  • contact_number 10 Digits
  • [FK] blood_group → STOCK
  • city, reg_date VARCHAR/DATE
DONATION Transaction
  • [PK] donation_id INTEGER (AI)
  • [FK] donor_id → DONOR
  • [FK] blood_group → STOCK
  • donation_date DATE
  • units_donated INT ≥ 1
  • hemoglobin_level ≥ 12.0 g/dL
HOSPITAL_REQUEST Transaction
  • [PK] request_id INTEGER (AI)
  • hospital_name VARCHAR(120)
  • [FK] blood_group → STOCK
  • units_requested INT > 0
  • urgency_level NORMAL/URGENT/CRITICAL
  • status PENDING/FULFILLED/REJECTED
Relational Mapping Rules & Cardinalities:
  • DONOR → DONATION (1 : N): A voluntary donor can donate multiple times over their lifetime; each donation record references exactly one donor.
  • DONATION → BLOOD_STOCK (N : 1): Every donation contributes blood units to the corresponding blood group inventory.
  • HOSPITAL_REQUEST → BLOOD_STOCK (N : 1): Every requisition references a blood group from the inventory; fulfilled requests decrement stock atomically.
  • Referential Integrity: Cascade deletion on donor removal; update cascade on blood group modifications.

                                🔷 UNIT 3: SOFTWARE DESIGN (Syllabus: Design Process & Concepts, Architectural Styles, Interface Design, Web-App Design)
                            

                            9 Hours Syllabus Coverage
                        


                        

                            

                                
1. Design Principles & Modularity

                                
    
                                    
  • Abstraction: High-level interfaces (DonorDAO, BloodStockDAO) separate contract from SQL execution.
    • 
                                    
  • Information Hiding: Domain models encapsulate state; mutations occur exclusively through validated methods.
    • 
                                    
  • High Cohesion: Each service handles exactly one bounded responsibility (DonorEligibilityService evaluates cooldown; InventoryService manages buffers).
    • 
                                    
  • Loose Coupling: Presentation layer connects via interfaces without direct SQL dependencies.
    • 
                                

                            


                            

                                
2. Web-App & Interface Design

                                
    
                                    
  • Responsive Single-Page Layout: Mobile and desktop accessible with clean CSS grid & flexbox.
    • 
                                    
  • Golden Rules Applied: Place user in control; reduce cognitive load; consistent visual vocabulary.
    • 
                                    
  • Color-Coded Visual Safety: Green badges for adequate stock (≥ threshold); flashing pulse warning for deficit groups.
    • 
                                    
  • Peter Chen ER Diagram Integration: High-resolution SVG canvas with interactive pan, zoom, and entity filters.
