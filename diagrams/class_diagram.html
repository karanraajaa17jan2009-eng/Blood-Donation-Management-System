📦 3-Compartment UML Class Structure

Following standard UML (ISO/IEC 19505), each class is strictly represented with three stacked compartments:

  • Top Compartment (Class Name): Represents the class identifier (e.g. Person, Donor, BloodStock). Stereotypes like <<Service>> denote architectural layers.
  • Middle Compartment (Attributes): Formatted as visibility name: type [= default]. Example: +age: int, -unitsDonated: int = 1.
  • Bottom Compartment (Operations / Methods): Formatted as visibility name(parameters): returnType. Example: +isAgeEligible(): boolean, +incrementStock(units: int): boolean.

🔗 Object-Oriented Relationships

  • Generalization / Inheritance (Δ hollow triangle): Donor, Phlebotomist, and HospitalRepresentative all inherit base demographic attributes (id, name, contactNumber) from the common parent class Person.
  • Directed Association (→): Donor "1" makes "0..*" Donation; each Donation increments "1" BloodStock; each HospitalRequest requisitions "1" BloodStock.
  • Dependency (..→): Business services (DonorEligibilityService, InventoryService) depend on domain models to perform clinical checks.
