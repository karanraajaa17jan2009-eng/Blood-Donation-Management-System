🔗 Relational Mappings & Cardinality Specifications

DONOR → DONATION: 1 : N (One-to-Many)
A single registered donor can have multiple historical donation records (or zero if first-time). Each donation belongs strictly to one donor.
DONATION → BLOOD_STOCK: N : 1 (Many-to-One)
Each donation event logs blood units collected and atomically increments the available inventory for that specific blood group.
HOSPITAL_REQUEST → BLOOD_STOCK: N : 1 (Many-to-One)
Hospital requisitions specify a required blood group. Upon fulfillment, units are decremented atomically from `BLOOD_STOCK`.
DONOR → BLOOD_STOCK: N : 1 (Many-to-One)
Every donor is categorized under one of the 8 ABO/Rh blood groups established in the master inventory.
Database Normalization Status: Fully compliant with Boyce-Codd Normal Form (BCNF). All functional dependencies have superkey determinants, eliminating insertion, deletion, and update anomalies.
